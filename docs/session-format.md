# RevDash Session Format v1

RevDash sessions are UTF-8 JSON Lines files with one complete JSON object per line. Every record has `schema_version: 1`, a `type`, and a non-negative integer `elapsed_us`. Integer microsecond offsets are measured from the monotonic start of the recording; wall-clock times, when present, are UTC strings in `YYYY-MM-DDTHH:MM:SS.sssZ` form. Consumers must not use UTC time for ordering or playback timing.

The final filename ends in `.jsonl`. Recording first writes the same basename with a `.partial` extension. A normal stop writes the footer, flushes and closes the file, then atomically renames it. A crash or write failure leaves the `.partial` file for inspection and future recovery; starting a new recording never overwrites an existing partial or final file.

## Record types

- `header` is first and has `elapsed_us: 0`. It contains the session UUID, application/schema versions, UTC start, source type, adapter and protocol key/value metadata, known vehicle/ECU metadata, and nullable simulation settings. UUIDs generated by RevDash are RFC 4122 variant, version 4 values.
- `obd_message` stores a canonical logical OBD payload, source type, sequence number, and nullable ECU identity. `payload_hex` is uppercase hexadecimal with no separators. Transport fragments are not stored as OBD messages.
- `telemetry` stores a canonical SI value, metric, unit, quality, sample timestamp, sequence, and ECU identity.
- `dtc` stores status, severity, description, likely failure points, ECU identity, and an optional freeze frame.
- `diagnostic_finding` stores the versioned heuristic, evidence, state, and all lifecycle offsets.
- `mode04_audit` stores the immutable clear-attempt audit, including pre-clear evidence, result/error, and post-clear DTCs.
- `ecu_metadata` stores VIN, calibration IDs, CVNs, protocol name, and ECU identity.
- `data_loss` records the positive count of records rejected since the previous marker because the bounded recorder queue was full. A marker makes the gap explicit but cannot reconstruct dropped content.
- `footer` is last and contains per-type counts, total records (including header and footer), and the sum of reported dropped records.

An ECU identity is either `null` or an object with numeric `value` and `format` (`can_11_bit`, `can_29_bit`, or `other`). Keeping the address width prevents equal numeric values on different address schemes from being conflated.

## Playback index

Playback creates a same-basename `.ridx` sidecar containing approximately one-second byte-offset checkpoints. The index records its own version, the session schema version, duration, source size, and a content fingerprint. It is a disposable cache: playback rebuilds it when it is missing, malformed, inconsistent with the validated checkpoints, or does not match the current session fingerprint.

## Compatibility and validation

Readers must reject unsupported `schema_version` values, unknown record types, missing required common fields, malformed JSON, decreasing `elapsed_us` values, and invalid hexadecimal payloads. The repository schema at `schemas/session-v1.schema.json` describes record-level structure. Cross-line rules—one header first, one footer last for completed sessions, and monotonic offsets—are stream validation rules implemented by playback rather than JSON Schema.

Object keys are emitted deterministically by the adopted JSON library, and the writer reuses a preallocated line buffer. This keeps fixture serialization stable and avoids buffer growth for normal telemetry records; filesystem writes remain streaming and never require retaining a session in memory.

## CSV export

Completed Session v1 recordings can be exported on a configurable uniform timeline (100 ms / 10 Hz by default). A value is held only through the metric's core stale interval; later rows contain an empty field. Conversion to Imperial units happens during export, while the session remains canonical SI.

The RevDash preset contains all catalogued metrics plus a small metadata preamble. MegaLogViewer and TunerStudio presets use conventional EFI Analytics channel labels and keep the CSV header as the first row. Units are tagged in every channel header. The compatibility layouts follow EFI Analytics' documented label-driven datalog model and MegaLogViewer HD's documented support for generic delimited logs; EFI Analytics does not publish one mandatory generic automotive CSV column schema, so these presets are RevDash-owned stable mappings rather than claims of a proprietary native format.

Exports are written to a temporary file in the destination directory and atomically replace the destination only after the stream has been flushed and closed.
